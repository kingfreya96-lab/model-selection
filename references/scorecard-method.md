# 评分卡方法（Scorecard Method）

## 1. 权重从失败模式反推

不要平均分配权重。规则：

- 你的**第一失败模式**对应维度权重最高（建议 ≥ 0.25）。
- 一票否决的约束不进入加权，直接在 `hard_exclusions_pass` 列判 FAIL 并淘汰。
- 权重总和必须为 1.0。

参考默认权重（编码/Agent 场景）：

| 维度 | 默认权重 | 何时调高 |
|---|---|---|
| domain_quality | 0.25 | 输出直接面向客户、错误代价高 |
| agentic_reliability | 0.25 | 多步工具调用是主流程 |
| context_effectiveness | 0.15 | 长文档 / 多轮是核心 |
| success_cost | 0.15 | 高并发、成本敏感 |
| latency_tail | 0.10 | 交互式、实时 |
| deploy_fit | 0.10 | 合规/私有化强约束 |

## 2. 0–10 打分锚点

每个维度用统一锚点，避免分数漂移：

| 分数 | 含义 |
|---|---|
| 9–10 | 业务评测集上通过率 ≥ 95%，无需人工干预 |
| 7–8 | 通过率 85–95%，偶发干预 |
| 5–6 | 通过率 70–85%，需规则兜底 |
| 3–4 | 通过率 50–70%，需较多人工 |
| 1–2 | 通过率 < 50%，不可直接上线 |
| 0 | 在该维度有硬伤 |

`success_cost` 用反向锚点：成本越低分越高。`latency_tail` 同理。

## 3. UNKNOWN 处理

- 没测过的维度记 `UNKNOWN`，**不要填中间值 5 分**。
- 若关键维度（权重 ≥ 0.2）为 UNKNOWN，该候选不得进入最终推荐，必须先补测。
- 允许非关键维度 UNKNOWN，但在决策简报中显式标注。

## 4. 加权公式

```
weighted_score = Σ (dimension_score_i × weight_i)   ，仅对已测维度
```

若存在 UNKNOWN，报告 `weighted_score_partial` 并注明覆盖率，例如：

```
weighted_score = 7.4 (覆盖权重 85%，deploy_fit 未测)
```

## 5. 成功成本（success-adjusted cost）

```
success_cost = 总服务成本 / 通过验收的请求数
            = (单价 × token 数 + 重试成本 + 人工修复成本) / 验收通过数
```

一个单价更高但修复轮次更少的模型，成功成本可能更低。**单价比价不构成选型依据。**

## 6. 样本量与统计

- 业务评测集建议 50–200 条真实样本；少于 30 条时结论标注"低置信"。
- 只对**前两名**做配对比较，记录逐条差异，不要一次排名 5 个模型。
- 差异在 ±3 个百分点内视为噪声，不据此决策。
