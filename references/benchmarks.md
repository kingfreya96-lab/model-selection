# 基准测试解读（Benchmarks: 测什么、别被什么骗）

## 使用原则

公开基准只用于**初筛和排除**，不用于最终决策。理由：饱和、污染、与生产约束脱节。

## 通用能力

| 基准 | 测什么 | 现状与陷阱 |
|---|---|---|
| MMLU | 57 学科多选题 | 已高度饱和，头部差距在噪声内；仅作能力底线粗筛 |
| MMLU-Pro | 更难的多学科推理 | 比 MMLU 有区分度，但仍偏学术 |
| GPQA | 研究生级科学问答 | 适合判断深度推理，不代表业务表现 |
| HellaSwag / ARC | 常识推理 | 饱和，参考价值低 |

## 代码

| 基准 | 测什么 | 现状与陷阱 |
|---|---|---|
| HumanEval / MBPP | 函数级代码生成 | 已污染/饱和，不建议用于 2026 年选型 |
| SWE-bench Verified | 500 条人工验证的真实 GitHub issue 修复 | 75+ 可视为具备真实软件工程能力；**必须区分 Verified 与 Pro（题源更难）** |
| SWE-bench Pro | 更难、更接近真实工程 | 分数普遍低于 Verified，比较时勿混用 |
| LiveCodeBench | 抗污染的持续更新题库 | 比 HumanEval 更可信，适合看趋势 |

## Agent / 工具调用

| 基准 | 测什么 | 现状与陷阱 |
|---|---|---|
| BFCL (Berkeley Function Calling) | 函数调用参数正确性 | 与你的 schema 仍有差异，必须自测 |
| τ-bench | 多轮工具调用 + 规则遵循 | 接近真实客服/Agent，值得参考 |
| WebArena / OSWorld | 网页/系统操作 | 成本高，看趋势即可 |

> **关键提醒**：Agent 场景不能只信榜单，必须在**你自己的工具 schema**上测函数调用合法率。高 SWE-bench 分不代表参数不报错。

## 对话 / 指令遵循

| 基准 | 测什么 | 现状与陷阱 |
|---|---|---|
| MT-Bench | 多轮对话质量 | 仅 80 条 prompt，统计稳健性有限 |
| Arena (Chatbot Arena) | 人类偏好 Elo | 反映偏好，不反映延迟/成本/稳定性 |
| IFEval | 指令遵循（格式约束） | 对结构化输出场景有参考价值 |

## 长上下文

| 基准 | 测什么 | 现状与陷阱 |
|---|---|---|
| RULER / 大海捞针 | 长上下文检索与推理 | 标称 1M ≠ 可用 1M；要在**目标长度**测中段召回 |
| LongBench | 长文档任务集合 | 更接近真实任务，建议自建同分布小集 |

## 多模态

| 基准 | 测什么 | 现状与陷阱 |
|---|---|---|
| MMMU | 多学科多模态理解 | 学术向，业务需自测票据/报表 |
| DocVQA | 文档问答 | 与 OCR+RAG 场景相关 |

## 结论

- 用基准做**排除**（某模型在与你场景最相关的基准上明显落后 → 淘汰）。
- 用**业务评测集**做**选择**（前两名配对比较）。
- 记录基准时同时记录版本日期，模型迭代后旧分失效。
