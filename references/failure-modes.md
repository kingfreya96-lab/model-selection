# 失败模式库（Failure Modes by Scenario）

选型的第一步不是看模型优点，而是列出"什么情况算失败"。本文件按场景给出常见失败模式与探针问题，用于 Workflow 第 1 步"失败契约"的引导。

## 使用方法

1. 让用户从对应场景中挑选 3–5 条最致命的失败模式。
2. 每条失败模式标注：是否一票否决（hard / soft）。
3. 将 hard 项直接映射到 scorecard 的硬排除列。

---

## 场景 A：编码 / 软件工程 Agent

| 失败模式 | 探针问题 | 默认级别 |
|---|---|---|
| 生成代码可运行但引入回归 | 是否有回归测试集？模型修复后回归率多少？ | hard |
| 工具调用参数不合法（schema 错） | 在你的 API spec 上函数调用成功率？ | hard |
| 多步任务中途丢失目标 | 长任务平均需要几轮人工干预？ | hard |
| 只能改单文件，无法跨文件推理 | 真实 issue 涉及文件数分布？ | soft |
| 修复轮次过多导致成本失控 | 平均修复轮次 / issue？ | soft |

## 场景 B：客服 / 对话机器人

| 失败模式 | 探针问题 | 默认级别 |
|---|---|---|
| 事实错误（幻觉政策、价格） | 是否有 golden answer 集？错误率？ | hard |
| 品牌语气不一致 | 有无语气 rubric 或人工验收？ | soft |
| 延迟超过用户容忍阈值 | P95 端到端延迟上限是多少秒？ | hard |
| 越权承诺（退款、赔偿） | 是否有拒答/转人工规则？模型遵守率？ | hard |
| 多轮上下文漂移 | 10 轮后仍能记住约束吗？ | soft |

## 场景 C：RAG / 长文档分析

| 失败模式 | 探针问题 | 默认级别 |
|---|---|---|
| 长上下文中段遗忘 | 在目标长度做"大海捞针"，中段召回多少？ | hard |
| 引用错位（张冠李戴） | 答案能否对齐到正确 chunk？ | hard |
| 标称上下文 ≠ 可用上下文 | 有效上下文（质量不降）是多少 token？ | hard |
| 长输入成本爆炸 | 目标文档长度下单次成本？ | soft |

## 场景 D：高并发 API / 生产服务

| 失败模式 | 探针问题 | 默认级别 |
|---|---|---|
| P99 触发 429 / 限流 | 你的峰值 QPS 与供应商配额比？ | hard |
| 延迟尾部抖动 | P99 TTFT / 端到端是否达标？ | hard |
| 供应商宕机无降级 | 是否有 fallback 模型且质量可接受？ | hard |
| 单位成本随重试放大 | 重试率 × 单价 = 实际成本？ | soft |

## 场景 E：多模态

| 失败模式 | 探针问题 | 默认级别 |
|---|---|---|
| 图表/表格解析错误 | 在你的票据/报表样本上准确率？ | hard |
| 图像细节丢失 | 小字、低分辨率图像识别率？ | soft |
| 图文混合指令遵循差 | 复合指令完成率？ | soft |

## 场景 F：合规 / 敏感数据

| 失败模式 | 探针问题 | 默认级别 |
|---|---|---|
| 数据出境 / 无法驻留 | 是否支持 VPC / 区域部署？ | hard |
| 无审计日志 | 是否提供调用审计？ | hard |
| 训练数据污染风险 | 是否承诺不用你的数据训练？ | hard |
| 内容安全策略不符 | 是否可配置审核策略？ | soft |

## 失败模式 → 评分维度映射

| 失败模式 | 对应评分维度 |
|---|---|
| 工具调用错误、多步规划失败 | agentic_reliability |
| 领域答案错误、验收不通过 | domain_quality |
| 长上下文遗忘、引用错位 | context_effectiveness |
| 成本随重试放大 | success_cost |
| 延迟尾部、限流 | latency_tail |
| 数据驻留、审计 | deploy_fit |
